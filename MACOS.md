# macOS / Apple Silicon

This branch adds a native ARM64 macOS build of the PC recompilation. The game code is compiled to Mach-O; SDL2 handles input/audio/windowing and ANGLE runs the existing GLES renderer through Metal. CrossOver is only a possible source of the game files.

## Requirements

- Apple Silicon Mac and Xcode command line tools. The code targets macOS 13+, but installed dependencies must support your OS; this local build was validated on macOS 26.6.2 with SDL2-compat 2.32.74 built for macOS 26.
- Homebrew `llvm`, `sdl2`, `python`, plus Git and Make. The local video decoder is built from pinned FFmpeg source and does not depend on Homebrew FFmpeg.
- Python packages `capstone==5.0.7` and `pefile==2024.8.26`.
- ARM64 ANGLE `libEGL.dylib` and `libGLESv2.dylib`. Setup can copy these from an installed Visual Studio Code or Claude; alternatively pass `--angle-dir /path/to/angle`. These libraries are local build dependencies and are not committed.
- Your game installation, with `FlatOut2.exe` MD5 `1f8cae2b47276ca134750ba438aa35ca`, `d3dx9_30.dll`, `filesystem`, and the BFS archives it lists. Some current Steam installations have this compatible Zoom executable; the checksum is what matters.

## Build

```sh
brew install llvm sdl2 python
python3 -m venv work/venv
work/venv/bin/pip install capstone==5.0.7 pefile==2024.8.26
work/venv/bin/python scripts/setup_macos.py --game-dir "/path/to/FlatOut 2"
work/venv/bin/python scripts/build_video_macos.py
work/venv/bin/python scripts/lift_macos.py
work/venv/bin/python scripts/build_macos.py
./Play.command
```

Setup pins `pcrecomp` to `35548b8d0fd8aa853da67edcf7cd6134f6b9cdc7`, applies the NFSU2 recompiler patches from `manuelpllull/nfsu2-recompiled-r36s` commit `50a2fe4b8037719c8ce577fbb4a471d5f2084d6b`, then applies the local catalog-memory patch and `scripts/patches/pcrecomp-fo2.patch` (x87 flag comparisons and conditional moves required by FlatOut 2, plus correct LOOP/JECXZ transfers across recovered function boundaries). Its runtime headers come from that same pinned NFSU2 commit. All dependency checkouts, generated C, objects, libraries and executables are under ignored `work/`.

EXE and DLL analysis run concurrently. Analysis needs several passes and can take a while. Generated files are reused on subsequent builds. After changing the executable, lifter or `config/`, remove `work/gen/` before lifting again. `JOBS=4` limits compilation concurrency; the default is six compiler processes. `CC` and `CXX` can override the Homebrew LLVM compilers.

The macOS build reserves the guest address space at 1 TB through Mach VM, outside the low-address region reserved by macOS; the guest still uses its original 32-bit addresses. The executable is `work/macos/fo2`. `Play.command` selects the local ANGLE libraries and defaults to a 1280×800 window and 60 FPS. Set `ANGLE_DEFAULT_PLATFORM=gl` to use ANGLE’s OpenGL backend instead of Metal. Override `FO2_RENDER` (render size) and `NFSU2_SCREEN` (window size) as needed. F10 closes the game. Keyboard and SDL gamepads use the upstream mappings. Launch logs go to `work/macos/play.log`; the preceding log is kept as `work/macos/play.previous.log`.

`gamedata/` is a separate local copy, using APFS copy-on-write when available. Its `Savegame/` is writable and independent of the source installation. Setup never overwrites an existing imported file or save. Neither game files nor saves belong in Git.

## Validation

`work/venv/bin/python tests/test_catalog_memory.py` compares compact and full-operand discovery for branches, jump tables and callbacks. `work/venv/bin/python tests/test_lift_boundaries.py` executes generated C to verify conditional tail transfers, fallthroughs and guest stack cleanup across catalog boundaries. D3DX lifting uses `--bounded` to partition reachable blocks at registered function entries. Cold blocks beyond the catalog size estimate stay in their caller when they have no dispatch entry; explicit fallthroughs preserve control flow across gaps. The PC EXE retains the upstream lift. D3DX uses the global x87 stack and Clang `musttail` transfers, so loops across recovered entries do not grow the native stack; the game code keeps the analyzed local-window optimization. The compact cache applies only to catalog discovery; lifting retains complete operands.

```sh
./work/macos/fo2 "$PWD/gamedata" --check-runtime
```

This does not open a window or start the game. It checks the 4 GB guest address space, PE loading and imports, guest heap/thread/input/audio-cap/file-time/critical-section self-tests (tests for imports not used by the game are skipped), generated callbacks, the lifted D3DX DLL initialization and headless vertex/pixel shader compilation. It exits nonzero on failure. Interactive rendering and a full race need a logged-in macOS desktop.

Linux-only `/proc` signal sampling and the hang watchdog are disabled on macOS; normal frame timing/FPS reporting remains available. LAN uses macOS socket wrappers and adapter enumeration; interoperability needs a separate multiplayer test.

The macOS runtime check passed on the compatible Steam/Zoom executable, including D3DX DllMain, its import bindings and real vertex/pixel shader compilation. ARM64 Mach-O signing verification and an ANGLE software-OpenGL pbuffer pixel readback also passed. A desktop launch also created the D3D9 device through ANGLE Metal on an Apple M3 Pro. It then exposed an unresolved D3DX cold-block transfer at `0x00AE121F`; the bounded lift now preserves that block, with executable regression coverage for missing dispatch entries. Menu rendering and a full race still need desktop validation.

For a native crash, macOS prints a minimal `[FO2 FAULT]` record before the detailed reporter, with PC/LR and the executable image base for symbolization. Guest threads use alternate signal stacks so an exhausted normal stack can still produce the record. `./work/macos/fo2 gamedata --check-crash-handler` deliberately raises SIGILL to test this path and exits unsuccessfully; `python3 tests/test_macos_crash_report.py` verifies the expected failure and report. This is a diagnostic check, not a game launch.

`python3 tests/test_native_tail.py` checks a million transfers with constant native stack usage. `python3 tests/test_d3dx_tail_loop.py` extracts the six generated D3DX functions from the reported `0x00AD70F2`–`0x00AD7187` loop: the old transfer reproduces a stack-overflow signal on the long workload, while the guaranteed tail transfer completes 1,048,576 vector accumulations with checked numeric results and guest stack cleanup. These checks need local generated code, but no desktop or GPU.

A subsequent desktop launch passed effect compilation, texture creation and CoreAudio initialization, then exhausted its 64 MB native stack in the split D3DX vector loop. Guaranteed native tail transfers fix the reproduced overflow; the exact-loop replay and headless shader compiler checks pass. Interactive menu and race validation remain outstanding.

## Socket address checks

Winsock IPv4 addresses use a little-endian 16-bit family at offset zero; Darwin instead stores an 8-bit length and an 8-bit family. The socket adapter explicitly converts both directions for bind/connect/send, peer/local addresses, receives and WSAIoctl route/interface results. Port and IPv4 bytes retain network byte order. `--check-runtime` verifies the actual guest-memory conversion, output length and guards without opening sockets.

Run `python3 scripts/check_network_macos.py --offline` for address ABI tests, omit `--offline` for TCP/UDP loopback, or use `--openspy` to also resolve and connect to `flatout2pc.ms8.openspy.net:28910`. `CheckNetwork.command` runs the last option from Terminal. Logs are `work/macos/network-offline.log`, `network-loopback.log` and `network-openspy.log`. The OpenSpy probe checks DNS and a TCP handshake only; obtaining a server list and joining a game still need an in-game test. Run the script in a normal user Terminal if the agent environment denies socket access.

For a server search which stalls after TCP connect, run `PlayNetwork.command`, try the search, then exit the game. `FO2_NET_TRACE=1` records bounded TCP send/recv results and select readiness; raw bytes are captured only for port 28910 under `work/macos/network-trace/<pid>/`. After exit the launcher replays the captured request in a standalone Python socket and writes `work/macos/openspy-replay.log`, distinguishing a missing master response from game-side receive/processing. It does not decrypt the server list or join sessions. `python3 scripts/replay_openspy.py --offline` inspects the latest capture without networking. Normal `Play.command` leaves this capture disabled.

Darwin `poll()` loses readiness when the same descriptor appears in multiple entries with different event masks. The Winsock `select` adapter now polls each native descriptor once with merged masks, then projects readiness into the separate guest sets. Pending-connect `SO_ERROR` is read once and retained for guest `getsockopt`. The offline network check reproduces the old lost response on a local stream socket pair, verifies the merged-mask result, EOF and successful/failed connection readiness. `--check-runtime` additionally calls the actual HLE `select` and `recv` with one stream in read+exception sets and validates response bytes and guest stack cleanup. No external network is required for these regressions.

## Native Metal backend (experimental)

The separate Metal build keeps the guest D3D9 ABI and the render-thread queue, then converts calls to owned resources and draw state in `runtime/render`. `runtime/d3d9_metal` implements the CPU adapter, shader translation and Objective-C++ GPU renderer. This binary links Metal directly, without ANGLE, EGL or GLES. The existing `Play.command` still selects GLES.

```sh
# Reuse already built guest objects:
python3 scripts/build_macos.py --renderer metal --host-only
# Or compile the lifted guest sources as well:
python3 scripts/build_macos.py --renderer metal
./TestMetal.command
# Subsequent launches:
./PlayMetal.command
```

The executable is `work/metal/fo2-metal`. It targets ARM64/macOS 13+, prefers the locally built macOS 13 SDL libraries in `work/portable-sdk/lib`, and otherwise uses installed SDL2. FFmpeg video decoding remains independent of the graphics backend.

Implemented paths include vertex/index buffers, converted RGBA and DXT textures, mip levels and cube faces, render/depth attachments, subresource views, locks/readback, scaled rectangle copies, recorded state blocks, declarations/FVF, fixed texture-stage operations, programmable shaders, depth/stencil/blending/scissor, alpha test, table/vertex fog, sRGB views, sampler LOD bias, presentation, screenshots and the FPS/virtual-keyboard overlay. The GPU consumes owned host data; no guest pointer survives a draw submission. One command queue and a two-slot semaphore bound submitted GPU work. Updated buffers/textures receive new GPU storage so earlier draws retain their original resources.

MojoShader's existing Metal profile is compiled unchanged. Project-owned wrappers handle BGRA inputs, uniform packing, D3D9 pixel centers, alpha test and fog. Captured bytecode goes to `work/metal/shaders`; translated source goes to `work/metal/msl`. Compiler/pipeline failures save MSL and diagnostics under `work/metal/failures`. Unsupported calls are logged and return failure; unsupported draw/shader paths raise an explicit error.

`TestMetal.command` enables Metal API and shader validation, checks GPU pixel readback (triangle/constants, depth, masks, scissor, partial clears, copies, alpha/blend), tests the D3D9 adapter (texture orientation, FVF/RHW, state-block capture/apply and BGRA readback), compiles eight HLSL fixtures through the lifted D3DX and Metal, then starts the game. Logs are `work/metal/check.log`, `work/metal/play.log` and `work/metal/play.previous.log`. Requested screenshots are PPM files under `work/metal/captures`. Every 300 frames the renderer reports FPS, draws/frame, CPU encoding time, GPU submission time and pipeline count.

CPU translation of all eight HLSL fixtures, structural checks of eight generated fixed-function shaders, and `--check-runtime` pass; both backend builds pass their runtime checks. The first desktop check on the user’s M3 Pro passed GPU drawing/readback and adapter tests, including sRGB and state blocks. The following shader-corpus gate failed on a literal-only pixel shader: the effects wrapper inserted a leading comma into an initially empty argument list. The wrapper is fixed and regression cases cover the shader with and without a fog input; all 11 captured shaders now pass CPU translation. GPU compilation of that fix and gameplay acceptance remain pending. This agent environment itself reports no Metal device and cannot open a desktop Terminal. A successful compile is not evidence of correct game rendering. Before replacing GLES, run the GPU checks and compare intro/menu, car selection, race, shadows/bloom/particles, pause, videos, input and network lobby; repeat a race for stability and compare frame captures/performance. The backend is scoped to FlatOut 2, not a complete D3D9 implementation. MSAA, volume textures, packed UDEC3/DEC3N attributes, generated FFP texture coordinates and some legacy shader instructions are unsupported and must fail explicitly. ## Metal launch profiles

All launchers remain in the repository root and accept the same extra game arguments. They share `TestMetal.command` / `PlayMetal.command`; no graphics mode is simulated by a launcher.

| Launcher | Gameplay profile |
| --- | --- |
| `PlayMetal.command` | Normal Metal executable, no preflight; API/shader validation defaults off. |
| `TestMetal.command` | GPU/runtime/shader preflight, then normal gameplay; ASan and geometry captures default off. |
| `TestMetalASan.command` | Preflight, then the accepted ASan executable; refuses an unavailable/stale diagnostic build instead of falling back. |
| `TestMetalGPU.command` | Normal executable with API/shader validation during gameplay; use for GPU correctness, not performance measurements. |

| `TestMetalNormals.command` | View-space geometric normals reconstructed from scene depth, encoded as RGB. |
| `TestMetalSSR.command` | Experimental screen-space reflections over the original color scene; F8 toggles the effect. |

Failure archives copy the failed run's own log. Independent session logs do not overwrite each other. ## Bounded raw geometry capture for RT preparation

The next preparation stage is an opt-in **shader-input geometry** snapshot, not a world-space RT scene. `runtime/render/trace_mesh.h` locates POSITION0 using the vertex shader's declared semantic/attribute slot, reads Float3 or homogeneous Float4(w=1), and owns a normalized float3/uint32 indexed triangle mesh. It respects stream/attribute offsets, stride, non-indexed vertexStart, indexed indexStart and signed baseVertex. Triangle strips preserve alternating winding and reset at 16/32-bit restart markers; repeated/collinear triangles are removed with a scale-relative area test. Nonfinite/out-of-range data, unsupported formats/instancing, incomplete triangle lists and input/output budgets return explicit statuses. Buffer address checks avoid integer multiplication overflow. Bounds use referenced vertices. Positions are copied; later guest/native buffer changes do not alter exported data.

`./TestMetalWater.command --rt-capture` enables a single bounded diagnostic frame after 120 consecutive presented racing frames (menu/pause resets the warmup). Eligible draws use the existing full-resolution perspective/depth-writing scene gate and additionally exclude blending, alpha testing and wireframe. This is a selection heuristic, not proof of a static vertex program. Limits per capture are 128 attempted draws, 400,000 budgeted input elements, 100,000 vertices, 100,000 triangles and 8 MiB of exported payload. Per-mesh vertex source/constants are capped at 128/16 KiB. Limit/unsupported/invalid/empty counters are preserved instead of silently including incomplete meshes. Geometry I/O failure disables the diagnostic and logs an error without terminating gameplay. Capture is disabled by default and does not modify game buffers, textures or saves.

The session's `rt-geometry/manifest.json` is atomically finalized after that frame. Per-mesh files contain little-endian raw positions, normalized triangle indices, the exact translated vertex shader and packed constant bytes.
